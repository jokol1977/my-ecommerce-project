# پیش‌پرواز پیکربندی Compose تولید

این بررسی پیش از انتشار، خطاهای رایج فایل `.env.production` را بدون چاپ مقدار رمزها پیدا می‌کند. از پوشهٔ ریشهٔ پروژه اجرا کنید:

```bash
chmod 600 .env.production
bash scripts/check-production-compose.sh
```

اسکریپت فقط فایل تنظیمات را می‌خواند و `docker compose config --quiet` را اجرا می‌کند. کانتینری شروع نمی‌شود، تصویری دریافت یا ساخته نمی‌شود و پایگاه‌داده، volume یا سرویس راه‌دور تغییر نمی‌کند. فایل باید معمولی، غیرپیوندی و با دسترسی `600` یا `400` باشد. قالب پذیرفته‌شده، خط‌های سادهٔ `KEY=value` بدون فاصله و بدون کوتیشن است؛ نمونهٔ `.env.production.example` همین قالب را دارد.

پیش‌پرواز، خالی‌نبودن تنظیمات ضروری و باقی‌نماندن placeholderهای نمونه را بررسی می‌کند، یکتایی و قالب URL-safe رمزها را می‌سنجد و تطابق رمزهای `DATABASE_URL`، `DIRECT_URL` و `REDIS_URL` را با متغیرهای متناظر می‌سنجد. `AUTH_SECRET` باید بین ۳۲ تا ۲۵۶ نویسه باشد. `APP_PORT` باید `3000` بماند تا port mapping وب با Nginx و اسکریپت دستی میزبان هماهنگ باشد؛ زمان‌بند اصلی Compose از نام سرویس `web:3000` استفاده می‌کند. فلگ‌های فروش باید دقیقاً `true` یا `false` باشند؛ فروش زنده در صورت فعال‌شدن مستلزم `AUTH_LOGIN_ENABLED=true` است، چون مشتری باید احراز هویت شود. پذیرش فروشنده نیز علاوه بر نیاز ورود، تا زمانی که برنامه پذیرش قرارداد نسخه‌دار را ذخیره و کنترل نکند باید `false` بماند؛ پیش‌پرواز فعلی مقدار `true` را رد می‌کند و کد runtime هم تأیید فروشنده را در production بسته نگه می‌دارد. حالت زرین‌پال در Compose تولید فقط `disabled` یا `production` است و حالت production به شناسهٔ پذیرنده با قالب UUID نیاز دارد. اگر فروش زنده با زرین‌پال غیرفعال تنظیم شود، پیش‌پرواز آن را رد می‌کند. ارائه‌دهندهٔ پیامک فقط `disabled` یا `kavenegar` است و حالت Kavenegar به کلید و فرستندهٔ غیرنمونه نیاز دارد. اگر `AUTH_LOGIN_ENABLED=true` باشد، تنظیمات SMTP، آدرس فرستندهٔ غیرنمونه و کلید رمزگذاری MFA با قواعد runtime سنجیده می‌شوند؛ کلید MFA باید کدگذاری canonical یک مقدار ۳۲‌بایتی Base64URL باشد. راز موقت ثبت عامل مدیر در صورت وجود باید واقعی و حداقل ۳۲ نویسه باشد، اما پس از ثبت TOTP می‌تواند از محیط حذف شود. خطاها فقط نام متغیر را نشان می‌دهند و مقدار secret را نمایش نمی‌دهند.

با وجود اعتبارسنجی قالب `MARKETPLACE_LIVE_CHECKOUT_ENABLED`، مقدار `true` فعلاً در پیش‌پرواز رد می‌شود؛ helper runtime نیز checkout تولید را مستقل از فلگ بسته نگه می‌دارد تا تأیید کتبی بازارگاه، بازپرداخت، تسویه، تطبیق مالی و پایلوت محدود انجام شوند.

اگر هر دو مقدار `PRODUCT_IMAGE_VOLUME_LIMIT_BYTES` و `PRODUCT_IMAGE_VOLUME_MIN_FREE_BYTES` عدد مثبتِ اندازه‌گیری‌شده نباشند، اسکریپت هشدار می‌دهد که بارگذاری تصویر کالا همچنان fail-closed است. این پیش‌پرواز جای بررسی ظرفیت واقعی volume، آزمون بازیابی بکاپ، بررسی دسترسی Docker، مهاجرت پایگاه‌داده، آزمون سلامت سرویس، HTTPS یا تأیید انتشار را نمی‌گیرد.

فایل `.env.production` واقعی در رایانهٔ فعلی موجود نیست؛ بنابراین این پیش‌پرواز فقط پس از آماده‌شدن تنظیمات واقعی روی میزبان مقصد قابل اجراست. برای آماده‌کردن آن، secret واقعی را در مخزن یا گفت‌وگو وارد نکنید.
