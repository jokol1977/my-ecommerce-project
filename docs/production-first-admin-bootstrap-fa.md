# چک‌لیست راه‌اندازی اولین مدیر در Production

**وضعیت:** نقش مدیر ایجاد و ممیزی شده؛ MFA فعال، رمز موقت حذف و ورود به پنل تأیید شده است  
**تاریخ:** ۲۲ نوامبر ۲۰۲۶  
**دامنه:** فقط حساب `admin@janankadeh.ir`

## وضعیت فعلی

- در ابتدای این فرایند، مالک حساب با ایمیل وارد شد و صفحهٔ حساب نقش `CUSTOMER` را نشان می‌داد.
- تأیید ایمیل به‌تنهایی حساب را مدیر نمی‌کند؛ نقش تازه‌ساخته‌شده به‌طور پیش‌فرض `CUSTOMER` بود.
- فرم عمومی یا API برای ثبت‌نام مدیر وجود ندارد. کد راه‌اندازی عامل دوم فقط برای حسابی با نقش `ADMIN` نشست محدود می‌سازد و خودش نقش را ارتقا نمی‌دهد.
- اسکریپت `scripts/bootstrap-local-admin.ps1` فقط برای پایگاه‌دادهٔ محلی است و برای Production نباید اجرا شود.
- درخواست نخست ارتقا رد شد. پس از پیگیری مجدد، تراکنش محدود Production برای همین حساب اجرا و نتیجه با اتصال برنامه بررسی شد.
- وضعیت فعلی تأییدشده: حساب هدف با نقش `ADMIN`، وضعیت `ACTIVE` و ایمیل تأییدشده؛ تنها مدیر Production؛ یک رویداد `INITIAL_ADMIN_BOOTSTRAPPED` برای حساب ثبت شده است.
- عامل TOTP فعال است و ۱۰ کد بازیابی استفاده‌نشده ثبت شده‌اند؛ مالک حساب اعلام کرده کدها را آفلاین ذخیره کرده است. مقدار کدها خوانده یا ثبت نشده است.
- خط `AUTH_ADMIN_MFA_ENROLLMENT_SECRET` از `.env.production` حذف شد. کانتینر `web` به‌تنهایی بازسازی شد؛ مقدار runtime این متغیر خالی است. فایل محیطی با مجوز `600` باقی ماند.
- پس از بازسازی، `web` سالم شد، صفحهٔ `/login` پاسخ `200` داد و پایگاه‌داده، Redis و زمان‌بند همچنان فعال بودند. رمز یا دادهٔ کاربر در خروجی‌ها نمایش داده نشد.

## پیش‌شرط مسیر مجاز Production

این عملیات باید توسط روال مدیریتی محدود و مورد تأیید Production انجام شود. اجرای آن از API عمومی، کنسول مرورگر، اسکریپت محلی یا دستور SQL کپی‌شده از گفتگو مجاز نیست.

اپراتور مجاز باید پیش از تغییر، فقط این موارد را به‌شکل محدود بررسی کند:

1. حساب هدف دقیقاً همان نشانی بالا، فعال و تأییدشده باشد.
2. هنوز مدیر Production دیگری وجود نداشته باشد. اگر مدیر دیگری وجود دارد، روال «اولین مدیر» متوقف شود.
3. عملیات فقط روی یک حساب اثر بگذارد. هر مغایرت در ایمیل، وضعیت، تعداد رکوردها یا نقش فعلی باعث توقف و بررسی مجدد شود.
4. مجوز تغییر مشخصاً به همین حساب و همین محیط Production مربوط باشد؛ هیچ نقش، فلگ پرداخت یا تنظیم ورود دیگری تغییر نکند.

## تغییر محدود و ثبت ممیزی

در روال تأییدشده، ارتقای نقش باید اتمیک باشد: ردیف حساب هدف قفل شود، پیش‌شرط‌ها در همان تراکنش دوباره بررسی شوند، فقط نقش همان حساب به `ADMIN` تغییر کند و رویداد `INITIAL_ADMIN_BOOTSTRAPPED` در گزارش ممیزی ثبت شود. اگر هر شرطی برقرار نبود، تراکنش باید بدون تغییر کامل لغو شود.

نتیجهٔ اجرای این مورد: فقط نقش حساب هدف تغییر کرد و یک رویداد ممیزی ثبت شد. بررسی پس از تراکنش نقش، فعال‌بودن، تأیید ایمیل، شمار مدیران و رویداد را تأیید کرد. هیچ حساب یا تنظیم دیگری در این عملیات تغییر نکرد. ایمیل‌های دیگر کاربران، کدها، رمزها و مقادیر محیطی خوانده یا در گزارش درج نشدند.

## تکمیل احراز هویت دومرحله‌ای مدیر

1. مالک حساب با رمز راه‌اندازی موقت وارد نشست محدود شد و TOTP را در برنامهٔ احراز هویت ثبت و تأیید کرد.
2. مالک حساب اعلام کرد ۱۰ کد بازیابی را ذخیره کرده است؛ مقادیر کدها دریافت یا ثبت نشده‌اند.
3. پس از فعال‌شدن TOTP، خط رمز راه‌اندازی موقت از `.env.production` حذف و فقط کانتینر `web` بازسازی شد. مقدار متغیر داخل کانتینر خالی است.
4. کنترل پایگاه‌داده پس از راه‌اندازی، نقش `ADMIN`، وضعیت `ACTIVE`، تأیید ایمیل، فعال‌بودن TOTP، ۱۰ کد بازیابی استفاده‌نشده، یک مدیر Production و یک رویداد ممیزی را تأیید کرد.
5. کنترل گرم پس از راه‌اندازی موفق بود: `web` سالم و `/login` با پاسخ `200`. مالک پس از ورود تازه، داشبورد `/admin` و صفحات مدیریتی سفارش‌ها، فروشندگان، دیدگاه‌ها، محصولات، دسته‌بندی‌ها، پشتیبانی، مالی و ممیزی را در Production باز کرد. صفحهٔ حساب نیز نقش مدیر را نشان داد. این کنترل فقط مشاهده‌ای بود و تغییری در سفارش، فروشنده، محصول یا پرداخت ایجاد نشد.

## شرایط توقف

اگر بازبینی امنیتی اعطای نقش ممتاز را رد کند، یا روال مدیریتی محدود Production در دسترس نباشد، عملیات باید متوقف بماند. این چک‌لیست مجوز دورزدن بازبینی نیست و خودِ آن نیز هیچ تغییری در سایت یا پایگاه‌داده ایجاد نمی‌کند.
