# چک‌لیست آمادگی پیش از خرید سرور

**آخرین بازبینی:** ۷ اکتبر ۲۰۲۶  
**وضعیت:** آماده‌سازی محلی تا حدی انجام شده؛ این سند تأیید نهایی برای خرید یا انتشار عمومی نیست.

## موارد انجام‌شده

- بررسی محلی برنامه، PostgreSQL، نقش محدود برنامه، مهاجرت‌های Prisma و نادیده‌گرفته‌شدن فایل‌های `.env` و پوشهٔ پشتیبان در Git با موفقیت انجام شد.
- بررسی راه‌اندازی محلی ۹ مورد را با موفقیت گذراند؛ اعتبارسنجی Prisma و ESLint روی کد برنامه و فایل‌های پیکربندی نیز موفق بود.
- پشتیبان محلی دیتابیس با نام `backups/janankadeh-20261007-125152-94766089.dump` ساخته شد و فهرست آرشیو آن قابل‌خواندن است.
- نسخهٔ محلی کد در `backups/janankadeh-source-20261007-final` با ۱۷۹ فایل ذخیره و بررسی شد؛ فایل محیطی واقعی، وابستگی‌ها و نسخه‌های پشتیبان در آن نیستند. این نسخه هنوز روی همان رایانه است و جای نسخهٔ خارج از دستگاه را نمی‌گیرد.
- دو کالای آزمایشی فقط در دیتابیس محلی قرار گرفتند. صفحهٔ اصلی، صفحات کالا و فروشگاه پاسخ HTTP موفق دادند؛ API سبد هم برای دو قلم موجودی و جمع ۴۸۰٬۰۰۰ تومان را درست گزارش کرد. این بررسی پرداخت یا ثبت سفارش انجام نداده است.
- دستورکار پیش‌فاکتور خریدار، رسید نهایی، حسابداری مدیر و صورت‌حساب فروشنده در `marketplace-financial-readiness.md` ثبت شد. این موارد پس از استقرار آزمایشی و پیش از فروش واقعی اجرا می‌شوند.
- راهنمای Docker، استقرار لینوکس، Nginx و HTTPS در پروژه موجود است؛ اجرای آن‌ها به سرور واقعی نیاز دارد.

## موارد باز پیش از اعلام آمادگی برای انتقال

1. **نسخهٔ منبع:** مخزن محلی هنوز هیچ commit ندارد و فایل‌های پروژه ثبت‌نشده‌اند. `.env` و پشتیبان‌ها از Git مستثنا هستند، اما هویت نویسندهٔ Git تنظیم نشده و remote هم وجود ندارد. نسخهٔ منبع باید پیش از انتقال قابل‌بازگشت و خارج از لپ‌تاپ هم پشتیبان‌گیری‌پذیر شود.
2. **آزمون دستی رابط:** در مرورگر، افزودن کالا، تغییر تعداد، حذف قلم، تازه‌سازی سبد و نمایش خطای موجودی کم هنوز از ابتدا تا انتها مرور نشده‌اند. پرداخت زنده در این مرحله نباید فعال شود.
3. **پاسخ نهایی میزبان:** قیمت و منابع پلن باید هنگام سفارش دوباره تطبیق داده شوند. سیاست عمومی میزبان می‌گوید مسئولیت نسخهٔ پشتیبان امن و خارج از شبکهٔ میزبان با مشتری است؛ قابلیت بکاپ پنل را فقط برای بازگشت به وضعیت قبلی/عیب‌یابی حساب می‌کنیم، نه نسخهٔ بحران. پس باید مقصد مستقل و رمزگذاری‌شدهٔ بکاپ و هزینه‌اش مشخص شود. حفاظت اختصاصی DDoS برای این پلن نیز در پاسخ دریافتی تأیید نشده است. هزینهٔ ترافیک اضافه، شرایط ارتقا و محدودهٔ پشتیبانی مدیریت سرور هم در برآورد نهایی لحاظ شوند.
4. **دسترسی‌های دامنه و اعلان:** برای استقرار به کنترل پنل DNS دامنه و یک نشانی ایمیل مدیریتی قابل‌استفاده برای ورود امن و اعلان‌ها نیاز است.

## ترتیب پس از تهیهٔ سرور

1. سخت‌سازی Ubuntu، ورود SSH با کلید، محدودسازی فایروال و اجرای Docker با PostgreSQL و Redis فقط در شبکهٔ داخلی.
2. استقرار خصوصی برنامه، اجرای مهاجرت‌ها، تنظیم Nginx و HTTPS، و آزمون عملی بکاپ و بازیابی روی VPS.
3. تکمیل پیش‌فاکتور/رسید و دفتر مالی مدیر و فروشندگان طبق `marketplace-financial-readiness.md`.
4. بازبینی قراردادی و مالیاتی، بازپرداخت و تطبیق درگاه؛ تا پایان این مراحل پرداخت زنده و پذیرش فروشنده خاموش بمانند.

## معیار اعلام آمادگی برای قرارداد VPS

اعلام آمادگی زمانی انجام شود که نسخهٔ منبع قابل‌بازگشت باشد، آزمون محلی سبد خرید تمام شود، موارد مبهم هزینه/بکاپ/حفاظت میزبان روشن شوند، و دسترسی DNS و ایمیل مدیریتی در دسترس باشد. آمادگی برای خرید VPS به معنی آمادگی برای فروش واقعی نیست.
