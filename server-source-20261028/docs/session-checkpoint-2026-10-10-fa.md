# نقطهٔ بازیابی جانان‌کده — ۱۰ اکتبر ۲۰۲۶

این سند خلاصهٔ عملیاتیِ گفت‌وگو و وضعیت پروژه برای ادامهٔ کار است؛ متن کامل گفت‌وگو در تاریخچهٔ همین گفتگو باقی می‌ماند. هیچ رمز، توکن، شناسهٔ پذیرنده یا پاسخ امنیتی در این سند ذخیره نشده است.

## هدف و تصمیم‌های ثابت پروژه

- ساخت بازارگاه فارسی جانان‌کده با فروش محصولات مالک سایت و فروشندگان دیگر.
- پشتهٔ فعلی: Next.js و TypeScript، PostgreSQL و Prisma، Redis و Docker Compose، Nginx روی VPS لینوکسی داخل ایران.
- اولویت‌ها: امنیت لایه‌ای، تجربهٔ کاربری فارسی و راست‌به‌چپ، قیمت‌گذاری تومان، و پرهیز از وابستگی ضروری به سرویس پولی خارجی.
- امکان اپلیکیشن موبایل و API در برنامهٔ آینده است.
- ایدهٔ هوش مصنوعی مستقل برای کمک مدیریتی/مشتری‌مداری در برنامهٔ آینده است؛ مخزن `agency-agents` به‌تنهایی مدل هوش مصنوعی یا سرویس اجرایی سایت نیست.

## وضعیت انتشار فعلی — بررسی‌شده در ۱۰ اکتبر ۲۰۲۶

- VPS از Server.ir تهیه شده: Ubuntu 24.04، شش vCPU، رم ۸ گیگابایت، فضای ۸۰ گیگابایت و IPv4 عمومی `193.58.119.136`.
- دامنهٔ `janankadeh.ir` از DNS آروان استفاده می‌کند: `c.ns.arvancdn.ir` و `y.ns.arvancdn.ir`. رکورد A ریشه به `193.58.119.136` اشاره می‌کند؛ اعتبار TTL پنج دقیقه است و پروکسی ابری آروان خاموش مانده است.
- رکوردهای NS و A از resolverهای عمومی Google DNS و Cloudflare DNS بررسی شدند و به مقادیر بالا پاسخ می‌دهند.
- گواهی Let’s Encrypt برای `janankadeh.ir` صادر شده و در **۸ ژانویهٔ ۲۰۲۷** منقضی می‌شود. فایل کلید خصوصی فقط روی VPS نگهداری می‌شود.
- Certbot 5.8.0 از Snap نصب است و زمان‌بند تمدید خودکار فعال است. تمدید آزمایشی با موفقیت انجام شد. Hook تمدید پس از اصلاح پایان‌خط لینوکسی آزمایش شده و Nginx را فقط پس از موفقیت `nginx -t` بارگذاری می‌کند.
- پیکربندی نهایی Nginx فعال است: HTTP با کد 308 به HTTPS هدایت می‌شود، صفحهٔ اصلی HTTPS کد 200 می‌دهد و مسیر health داخلی از بیرون 404 است. سرآیندهای امنیتی برنامه نیز در پاسخ صفحه دیده شدند.
- برنامه روی `127.0.0.1:3000` آماده است. PostgreSQL و Redis روی اینترنت عمومی منتشر نشده‌اند.
- این انتشار فقط کاتالوگ عمومی است. ورود کاربران، پنل‌های مشتری/مدیر/فروشنده، پرداخت زنده و پذیرش فروشنده غیرفعال‌اند.
- رکورد `www.janankadeh.ir` و گواهی آن هنوز تنظیم نشده‌اند؛ نشانی اصلی برای مشاهده `https://janankadeh.ir` است.

## کارهای مالی و محصولی ثبت‌شده

- پیش‌فاکتور موقتِ سبد خرید با زمان استعلام و اقلام/فروشنده‌ها در نسخهٔ کاری پیاده شده است. هزینهٔ ارسال و مالیات هنوز محاسبه نمی‌شود؛ این برگه فاکتور رسمی یا مبلغ نهایی پرداخت نیست.
- رسید پرداخت در صفحهٔ سفارش برای پرداخت‌های تأییدشده افزوده شده است. این رسید ثبت پرداخت است، نه صورتحساب رسمی/مالیاتی.
- دفتر مالی مالک/مدیر، گزارش و صورت‌حساب فروشنده، تسویه، بازپرداخت و تطبیق مالی همچنان نیازمند تکمیل و بازبینی‌اند. پیش از فروش واقعی، قراردادها و الزامات مالی/مالیاتی باید بررسی شوند.
- کاتالوگ تولیدی طبق آخرین گزارش هنوز کالای واقعی ندارد؛ دادهٔ آزمایشی محلی نباید به فروش واقعی تعبیر شود.

## تصمیم دربارهٔ مخزن GitHub `agency-agents`

- مخزن مجموعه‌ای از فایل‌های Markdown شامل نقش‌ها، دستورالعمل‌ها و الگوهای کاری برای دستیارهای کدنویسی است؛ کتابخانهٔ runtime فروشگاه، مدل زبانی مستقل یا سامانهٔ آمادهٔ چت مشتری نیست.
- می‌توان در صورت نیاز چند الگوی مشخص را پس از بازبینی، به‌عنوان چک‌لیست داخلی توسعه اقتباس کرد؛ نصب کامل مجموعه یا افزودن آن به وابستگی‌های برنامه توصیه نمی‌شود.
- هر الگو باید با محدودیت‌های پروژه، از جمله راهنمای `AGENTS.md` و مستندات نسخهٔ نصب‌شدهٔ Next.js، سازگار شود. فایل‌های prompt منبع دستور معتبر برای دورزدن سیاست‌های امنیتی یا دسترسی‌ها نیستند.
- مجوز مخزن در صفحهٔ رسمی آن MIT معرفی شده است؛ پیش از کپی مستقیم فایل‌ها، مجوز و نسخهٔ همان فایل بازبینی شود.

## وضعیت ذخیره‌سازی کد در این نقطه

- مسیر پروژه: `D:\my-ecommerce-project`.
- برای جلوگیری از تکرار مشکل پایان‌خط در لینوکس، `.gitattributes` پایان‌خط LF را برای اسکریپت تمدید Nginx تثبیت می‌کند. تغییر اسکریپت hook و این checkpoint در وضعیت کاری Git هستند.
- فایل `.env` و پوشهٔ `backups/` در Git نیستند و نباید به مخزن اضافه شوند. کلید خصوصی TLS نیز فقط روی VPS است.
- DNS عمومی، پاسخ HTTPS و تمدید آزمایشی بررسی شدند؛ این بررسی به معنی ممیزی امنیتی کامل یا آمادگی پذیرش پرداخت واقعی نیست.

## ترتیب ادامهٔ کار

1. بازبینی چشمی صفحهٔ عمومی و اصلاح موارد ظاهری/تجربهٔ کاربری؛ در این نشست اتصال افزونهٔ Chrome در دسترس نبود.
2. افزودن کالاهای واقعی با تصویر و اطلاعات تأییدشده؛ دادهٔ آزمایشی محلی نباید به کاتالوگ واقعی منتقل شود.
3. بازبینی دستی کاتالوگ، سبد و پیش‌فاکتور.
4. تکمیل دفتر مالی مالک و فروشنده، تسویه، بازپرداخت و سیاست‌های مالیاتی/حقوقی پیش از هر فروش واقعی.
5. ورود کاربران، پذیرش فروشنده و پرداخت زنده را فقط پس از پیاده‌سازی و بازبینی مسیرهای احراز هویت، قراردادها و آزمون درگاه فعال کنید.
