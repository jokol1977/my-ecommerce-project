## موارد باز پیش از اعلام آمادگی برای انتقال

1. **نسخهٔ بیرون از دستگاه:** commit محلی ایجاد شده، ولی Git remote یا نسخهٔ منبع بیرون از لپ‌تاپ نداریم. پیش از انتقال فایل‌ها به VPS، نسخهٔ منبع را از مسیر امن به سرور منتقل و یک کپی مستقل خارج از سرور نگه می‌داریم.
2. **آزمون دستی رابط:** در مرورگر، افزودن کالا، تغییر تعداد، حذف قلم، تازه‌سازی سبد و نمایش خطای موجودی کم هنوز از ابتدا تا انتها مرور نشده‌اند. پرداخت زنده در این مرحله نباید فعال شود.
3. **پاسخ نهایی میزبان:** قیمت و منابع پلن باید هنگام سفارش دوباره تطبیق داده شوند. سیاست عمومی میزبان می‌گوید مسئولیت نسخهٔ پشتیبان امن و خارج از شبکهٔ میزبان با مشتری است؛ قابلیت بکاپ پنل را فقط برای بازگشت به وضعیت قبلی/عیب‌یابی حساب می‌کنیم، نه نسخهٔ بحران. پس باید مقصد مستقل و رمزگذاری‌شدهٔ بکاپ و هزینه‌اش مشخص شود. حفاظت اختصاصی DDoS برای این پلن نیز در پاسخ دریافتی تأیید نشده است. هزینهٔ ترافیک اضافه، شرایط ارتقا و محدودهٔ پشتیبانی مدیریت سرور هم در برآورد نهایی لحاظ شوند.
4. **دسترسی‌های دامنه و اعلان:** برای استقرار به کنترل پنل DNS دامنه و یک نشانی ایمیل مدیریتی قابل‌استفاده برای ورود امن و اعلان‌ها نیاز است.

## ترتیب پس از تهیهٔ سرور

1. سخت‌سازی Ubuntu، ورود SSH با کلید، محدودسازی فایروال و اجرای Docker با PostgreSQL و Redis فقط در شبکهٔ داخلی.
2. استقرار خصوصی برنامه، اجرای مهاجرت‌ها، تنظیم Nginx و HTTPS، و آزمون عملی بکاپ و بازیابی روی VPS.
3. تکمیل پیش‌فاکتور/رسید و دفتر مالی مدیر و فروشندگان طبق `marketplace-financial-readiness.md`.
4. بازبینی قراردادی و مالیاتی، بازپرداخت و تطبیق درگاه؛ تا پایان این مراحل پرداخت زنده و پذیرش فروشنده خاموش بمانند.
